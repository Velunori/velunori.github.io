Before you begin.

Velunori needs an existing Omarchy installation with the shell plugin API. Run the installer from an unlocked desktop terminal, as your normal user. Do not run it with sudo.

Omarchy
Components are checked on 4.5.0-3. Other releases may need compatibility work; there is no promise of compatibility with every release. The lock screen installer checks that its service matches your installed Omarchy service.
Tools
Bash, Python 3, curl for downloading the installer, and the existing Omarchy commands. Python venv/pip is needed only when cloud libraries are selected. Components also use pactl, ip, hyprctl, systemd-run and checkupdates.
Network
Needed to download the installer and, if selected, install calendar dependencies. The component sources are included in the script. Weather and cloud synchronization also require network access.
Location
Plugins and the library are copied into the Omarchy plugins directory. Receipts, backups and the retained installer use ~/.local/share/velunori/installation by default; no checkout or workspace shortcut is needed.

What installation changes. Velunori enables the selected shell components, replaces their corresponding built-in panels and restarts the shell. If selected, the theme is applied immediately. It does not install system packages, run a system update, lock the desktop or connect calendar accounts.

Already using Velunori from individual source checkouts? The installer refuses to overwrite those links. Disable or remove that installation first, following each component's restore instructions.

Review before applying. The script checks prerequisites, prints your selection and asks you to confirm with yes or no. No installer plugin or bar icon is added.

Your choices matter. Floating Bars changes your bar; Dusk applies a theme and wallpaper; Serene replaces lock-screen presentation. Leave them unchecked to retain those parts of your desktop.

Inspect the plan first

To choose interactively, run curl -fsSL https://velunori.github.io/install.sh | bash. The script reads choices from your terminal even though its source arrives through a pipe. After downloading the script, run bash velunori-install.sh plan --components control-center to inspect a selection without desktop queries or installation. Use check instead of plan for read-only prerequisite checks. The install action runs those checks itself and requires confirmation.

The supported component names are bar, clock, control-center, notifications, menu, weather, update, lockscreen and theme. Use --all or --components clock,control-center. Add --cloud only with the clock. The library is resolved automatically.

The payload contains the compatible source snapshot, including licenses. It creates real copied plugin and library directories, not source links. The embedded checksum detects corruption; it is not an independent publisher signature. Download only from the official published site and review the script/source before installation.

Make it yours.

Open Appearance from Control Center, or use the command below. Choose Island or Orbit, pick Lavender, Mint or Pearl, and set your animation preference. Preview changes on your desktop, then Apply or Cancel.

Appearance settings
omarchy-shell velunori settings

  • Use the calendar's source filters and selected-day agenda. Local calendars remain available without connecting an account.
  • Manage saved weather cities from the forecast panel. The primary city appears in the bar.
  • Open the bell to view notifications from the current session. Notification history is not persistent.
  • Serene has a preview mode that does not lock the desktop or accept a password. Use omarchy-shell lock preview and click the preview to dismiss it.

Bring your calendars.

Local calendar data persists between sessions. Google and iCloud synchronization are optional and require an explicit account connection in the calendar panel.

  • Google: open Calendars → Add account → Google → Connect Google, then approve calendar access in your browser. The published installer includes Velunori’s desktop app registration; no personal Google Cloud project or JSON file is needed.
  • iCloud: open Calendars → Add account → iCloud and enter your Apple Account email and app-specific password. Birthdays generated from Contacts are outside this CalDAV integration.
  • Recurrence: existing recurring events are expanded into occurrences. Individual occurrences can be edited or removed; creating recurrence rules and editing whole series are not supported.

If you skipped cloud dependencies at installation, add them later from the bundle checkout:

Enable cloud calendar libraries
bash ~/.config/omarchy/plugins/velunori.clock/scripts/setup-deps.sh
omarchy restart shell

Cloud sign-in and writes still need live-account verification. Credentials are stored privately on disk without encryption. Do not include them or private events in issue reports. Read the calendar setup and synchronization guide before connecting an account.

Keep track of your installation.

This preview supports plan, check, install and status. In-place upgrades and a managed removal command are not implemented yet. It refuses to overwrite existing plugin paths or an existing receipt directory.

Installed version and selection
bash ~/.local/share/velunori/installation/installer.sh status

The default receipt/backup directory is ${XDG_DATA_HOME:-$HOME/.local/share}/velunori. If you selected a different --prefix, run the retained installer from that directory with the same prefix argument.

Already installed from a Git bundle or development links? Keep that installation in place and follow its existing update instructions. This new script does not silently migrate it. Updating Velunori remains separate from updating Omarchy itself.

Keep a way back.

The script saves backups/shell.before.json and installation.json in its receipt directory before activating plugins. Do not delete that directory while diagnosing an incomplete installation.

If activation fails and the shell configuration still matches the installer’s version, it attempts to restore the original configuration and moves new plugin files into recovery/, retaining them rather than deleting them. If it detects concurrent configuration edits or cannot restart the restored shell, it retains the installed files and marks the receipt needs-recovery.

Manual recovery

Read the printed receipt and error first. Back up your current shell.json, review the saved pre-install snapshot, then restore that snapshot only if replacing later shell changes is intended. Restart the shell from an unlocked desktop afterward. Theme restoration is separate; the receipt records the previous theme when Dusk was selected. Cloud dependencies and persistent calendar data are not erased by recovery.

To remove a copied feature through Omarchy, disable it and use its normal plugin-removal command. Switch to omarchy.bar before removing Floating Bars. Keep the shared plugins/lib directory while any component requires it. A coordinated removal/update workflow will be added later.

Return to the stock bar
omarchy plugin enable omarchy.bar

If something feels off.

Missing components or scripts

Download a fresh copy of the complete installer if its embedded payload or file inventory fails validation. Do not bypass the checksum.

Another installation already exists

The installer will not replace unrelated plugin paths. Check whether your existing components are linked from an older checkout. Use their existing installers or restore instructions before migrating; keep the original source available until those links are removed.

The lock service does not match

A newer Omarchy release may have changed its lock service. Leave Serene unchecked in your selection and report the version mismatch to the lock screen repository. Do not bypass the service check.

A panel is misplaced, clipped or unresponsive

Report the affected component, Omarchy version, source commit, monitor resolution, scale, bar layout and reproduction steps. A screenshot with sample data helps. Offscreen checks do not verify live panel placement, scrolling or authentication.

The shell crashed

Consult the bar's stability notes and include relevant crash metadata when reporting it. A crash in Qt or Quickshell needs evidence before attributing it to a component. Do not attach raw core dumps or unreviewed diagnostic archives containing personal data.

A little help, together.

Installation and bundle problems belong in the main repository. For a component bug, use that component's issue forms. Include your Omarchy version, installation method and relevant commit; the installer receipt records its version, build and selected components.
